## 1) Импорт файлом — архитектура (BulkImportService vs новая структура)

**Коротко (решение):**  
✅ **Оставляем существующий** `app/Services/AccessHub/Admin/BulkImportService` как “ядро” импорта и **расширяем его**.  
❌ **Полную замену на новую структуру** из TZ last.md сейчас **не делаем**, чтобы не ломать работающий импорт и не растягивать сроки.

**Почему:**
- В ТЗ важно наличие функционала “импорт файлами”, а не конкретный namespace/DTO.
- У вас уже есть протестированный `importFromText()` и логика dedupe/skip.
- Рефактор в новый namespace оправдан только если текущий код трудно расширять — это не требование ТЗ.

**Как сделать правильно без “грязи”:**
- Добавить метод `importFromFile()` в `BulkImportService`, который:
	- определяет тип файла (txt/csv/xlsx),
	- превращает содержимое в **тот же формат**, который умеет `importFromText()` (многострочный текст `|`), **или** формирует массив строк и переиспользует общую функцию обработки строки.
- Парсеры TXT/CSV/XLSX можно:
	- сделать приватными методами в сервисе (минимально),
	- или вынести в `app/Services/AccessHub/Admin/ImportParsers/*` (аккуратнее, но без полной перестройки DTO).

## 2) Импорт файлом — можно ли переиспользовать BulkImportService::importFromText()

**Коротко (решение):**  
✅ Да, **можно и нужно переиспользовать** существующую логику `importFromText()`.

**Рекомендуемый путь (минимум изменений, без DTO):**
- TXT:
	- `file_get_contents()` → передать текст как есть в `importFromText()`.
- CSV/XLSX:
	- распарсить в строки,
	- собрать “каноническую” строку:  
	  `platform | game | game_login | game_password | email_login | email_password | backup_emails`
	- склеить строки через `\n` → вызвать `importFromText()`.

**Когда нужен DTO/рефактор:**
- если `importFromText()` внутри смешивает “парсинг” и “сохранение” так, что добавление CSV/XLSX превращается в дублирование кода.
- тогда минимальный рефактор: выделить метод уровня строки, например:
	- `importParsedRow(array $row): ImportRowResult`
а `importFromText()`/`importFromFile()` будут только формировать `row` и вызывать его.

**Итог:** DTO из TZ last.md — **опционально**. ТЗ не требует DTO.

## 5) Валидация платформ при импорте — сейчас или позже

**Коротко (решение):**
✅ Реализуем валидацию **с режимом “не блокировать, пока список не финальный”**:

- В `config/accesshub.php`:
	- `platforms` по умолчанию = `[]` (пусто)
- В импорте:
	- если список **пустой** → **не валидировать** (принимать любые непустые значения)
	- если список **не пустой** → валидировать строго (иначе строка уходит в `errors`)

**Почему:**
- В ТЗ “строгий список платформ” есть, но у вас **нет финального списка** от заказчика.
- Жёсткая валидация по временно-неполным значениям может “сломать” импорт реальных данных.

**Формулировка правила (как писать в коде):**
- `if ($allowedPlatforms !== [] && !in_array($platform, $allowedPlatforms, true)) -> errors[]`
