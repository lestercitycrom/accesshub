# Шаг 3: Тестирование админской части AccessHub

После реализации админских функций (шифрование, мастер `/add`, импорт `/import`, логи `/log`) можно приступать к тестированию админских возможностей бота.

---

## Подготовка перед тестированием

### 1. Убедитесь, что вы добавлены как администратор
```bash
php artisan accesshub:user:add <your_telegram_id> admin
```

Чтобы узнать свой Telegram ID, можно использовать бота [@userinfobot](https://t.me/userinfobot) или посмотреть в логи при первом обращении к боту.

### 2. Проверьте наличие тестовых аккаунтов
```bash
php artisan accesshub:account:seed-test
```

Список созданных тестовых аккаунтов см. в `docs/test_accounts.md`.

## Тест 1: Шифрование чувствительных полей

### Проверка через tinker

1. Откройте tinker:
```bash
php artisan tinker
```

2. Создайте тестовый аккаунт с чувствительными данными:
```php
$a = \App\Models\Account::create([
	'platform' => 'Xbox X',
	'game' => 'Minecraft',
	'game_login' => 'enc_test_login',
	'game_password' => 'enc_test_pass',
	'email_login' => 'enc@test.com',
	'email_password' => 'mail_pass',
	'max_uses' => 3,
	'available_uses' => 3,
	'is_active' => true,
]);
```

3. Проверьте, что данные читаются корректно:
```php
$a->fresh()->game_password;  // Должно вернуть: "enc_test_pass"
$a->fresh()->email_login;   // Должно вернуть: "enc@test.com"
$a->fresh()->email_password; // Должно вернуть: "mail_pass"
```

### Проверка в базе данных

Проверьте, что в MySQL поля хранятся в зашифрованном виде:

```sql
SELECT id, game_login, game_password, email_login, email_password 
FROM accounts 
WHERE game_login = 'enc_test_login';
```

**Ожидаемый результат:**
- `game_password`, `email_login`, `email_password` содержат **нечитаемый шифротекст** (не "enc_test_pass", а что-то вроде "eyJpdiI6...")
- При чтении через Eloquent данные автоматически расшифровываются

3. **Логин игрового аккаунта:**

4. **Пароль игрового аккаунта:**

## Тест 3: Команда `/import` (массовый импорт)

### 3.1 Импорт текстом (в одном сообщении)

Отправьте боту:
```
/import
Xbox X | Forza Horizon 5 | forza_user_1 | forza_pass_1 | forza@mail.com | mailpass1 | backup@mail.com
Xbox X | Forza Horizon 5 | forza_user_2 | forza_pass_2 | - | - | -
PS5 | God of War | gow_user_1 | gow_pass_1 | gow@mail.com | mailpass2 | -
```

**Ожидаемый результат:**
```
Импорт завершён.
Добавлено: 3
Пропущено: 0
Ошибок: 0
```

### 3.2 Импорт текстом (многострочный)

Отправьте боту:
```
/import
```

Затем отправьте следующее сообщение:
```
Steam | Portal 2 | portal_user_1 | portal_pass_1 | portal@mail.com | mailpass3 | -
Steam | Portal 2 | portal_user_2 | portal_pass_2 | - | - | -
# Это комментарий - будет пропущен
Epic | Rocket League | rl_user_1 | rl_pass_1 | rl@mail.com | mailpass4 | backup1@mail.com, backup2@mail.com
```

**Ожидаемый результат:**
```
Импорт завершён.
Добавлено: 3
Пропущено: 0
Ошибок: 0
```

**Примечание:** Строки, начинающиеся с `#`, игнорируются.

### 3.3 Импорт из файла

1. Создайте файл `import.txt` с содержимым:
```
Nintendo | Super Mario Odyssey | mario_user_1 | mario_pass_1 | mario@mail.com | mailpass5 | -
Nintendo | Super Mario Odyssey | mario_user_2 | mario_pass_2 | - | - | -
Switch | Animal Crossing | ac_user_1 | ac_pass_1 | ac@mail.com | mailpass6 | backup@mail.com
```

2. Отправьте файл боту как документ (не фото!)

**Ожидаемый результат:**
```
Импорт из файла завершён.
Добавлено: 3
Пропущено: 0
Ошибок: 0
```

### 3.4 Формат импорта

**Формат строки:**
```
Platform | Game | game_login | game_password | email_login | email_password | backup_emails
```

**Правила:**
- Минимум 4 поля обязательны (Platform, Game, login, password)
- Опциональные поля можно указать как `-` или оставить пустыми
- `backup_emails` можно указать через запятую: `mail1@mail.com, mail2@mail.com`
- Строки, начинающиеся с `#`, игнорируются

**Примеры:**
```
# Полный формат
Xbox X | Minecraft | user1 | pass1 | email@mail.com | emailpass | backup@mail.com

# Без email
Xbox X | Minecraft | user2 | pass2 | - | - | -

# С несколькими backup email
Steam | CS2 | user3 | pass3 | email@mail.com | emailpass | backup1@mail.com, backup2@mail.com
```

## Что проверять при тестировании

### ✅ 1. Шифрование работает
- Чувствительные поля (`game_password`, `email_login`, `email_password`) хранятся в БД в зашифрованном виде
- При чтении через Eloquent данные автоматически расшифровываются
- Проверьте через SQL запрос, что в БД лежит шифротекст

### ✅ 2. Мастер `/add` работает корректно
- Мастер запускается командой `/add`
- Все шаги проходятся последовательно
- Опциональные поля можно пропустить через `skip`
- Мастер можно отменить через `/abort`
- После завершения аккаунт создаётся в БД
- Только администраторы могут использовать мастер

### ✅ 3. Импорт `/import` работает
- Импорт текстом в одном сообщении работает
- Импорт многострочным текстом работает
- Импорт из файла (документ) работает
- Дубликаты корректно пропускаются (не создаются повторно)
- Ошибки формата обрабатываются
- Комментарии (строки с `#`) игнорируются
- Только администраторы могут импортировать

### ✅ 4. Логи `/log` работают
- Показываются последние 10 выдач по аккаунту
- Отображается правильная информация (дата, order_id, operator)
- Для аккаунтов без логов показывается соответствующее сообщение
- Неверный формат обрабатывается с подсказкой
- Только администраторы могут просматривать логи

### ✅ 5. Права доступа
- Операторы не могут использовать админские команды (`/add`, `/import`, `/log`)
- Неавторизованные пользователи получают сообщение "Нет доступа"
- Только администраторы имеют доступ к админским функциям

## Проверка через базу данных

### Посмотреть все аккаунты с зашифрованными полями
```sql
SELECT 
    id,
    platform,
    game,
    game_login,
    game_password,  -- Должен быть шифротекст
    email_login,    -- Должен быть шифротекст
    email_password, -- Должен быть шифротекст
    codes_receiver_emails,
    platform_meta,
    available_uses,
    max_uses,
    is_active,
    created_at
FROM accounts
ORDER BY id DESC
LIMIT 10;
```

### Проверить логи выдач по аккаунту
```sql
SELECT 
    il.id,
    il.order_id,
    il.operator_telegram_id,
    il.issued_at,
    a.game,
    a.platform,
    a.game_login
FROM issuance_logs il
JOIN accounts a ON il.account_id = a.id
WHERE il.account_id = 1
ORDER BY il.issued_at DESC
LIMIT 10;
```

### Статистика импорта
```sql
SELECT 
    DATE(created_at) as date,
    COUNT(*) as accounts_added,
    platform,
    game
FROM accounts
WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY)
GROUP BY DATE(created_at), platform, game
ORDER BY date DESC, platform, game;
```

### Проверить уникальность аккаунтов
```sql
SELECT 
    platform,
    game,
    game_login,
    COUNT(*) as duplicates
FROM accounts
GROUP BY platform, game, game_login
HAVING duplicates > 1;
```

**Ожидаемый результат:** Пустой результат (все аккаунты уникальны по комбинации platform + game + game_login).

## Частые проблемы и решения

### Мастер `/add` не запускается

1. **Проверьте права:**
   ```sql
   SELECT * FROM telegram_users WHERE telegram_id = '<your_telegram_id>' AND role = 'admin';
   ```

2. **Добавьте себя как администратора:**
   ```bash
   php artisan accesshub:user:add <telegram_id> admin
   ```

### Импорт не работает

1. **Проверьте формат:** Должно быть минимум 4 поля, разделённые `|`
2. **Проверьте права:** Только администраторы могут импортировать
3. **Проверьте файл:** При импорте из файла убедитесь, что отправляете документ (не фото)

### Логи не показываются

1. **Проверьте account_id:** Убедитесь, что аккаунт с таким ID существует
2. **Проверьте, были ли выдачи:**
   ```sql
   SELECT COUNT(*) FROM issuance_logs WHERE account_id = <account_id>;
   ```

### Шифрование не работает

1. **Проверьте APP_KEY:** Убедитесь, что в `.env` установлен `APP_KEY`
2. **Проверьте через tinker:**
   ```php
   $a = \App\Models\Account::find(1);
   $a->game_password; // Должно расшифроваться автоматически
   ```

### Ошибка "Нет прав"

1. **Проверьте роль пользователя:**
   ```sql
   SELECT role FROM telegram_users WHERE telegram_id = '<telegram_id>';
   ```

2. **Измените роль на admin:**
   ```sql
   UPDATE telegram_users SET role = 'admin' WHERE telegram_id = '<telegram_id>';
   ```
