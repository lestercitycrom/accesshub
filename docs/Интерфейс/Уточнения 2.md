## 1) `$this->md->codeBlock()` — откуда `$this->md`

**Правильно:** да, нужен отдельный сервис (или трейт/хелпер) для формирования code-block, потому что `TelegramApiClient` отвечает только за отправку, а не за форматирование.

### Вариант “лучше” (рекомендую)

* Оставляем `App\Services\Telegram\TelegramMarkdown` (как мы делали раньше)
* Внедряем в `AccessHubBotService` через DI:

```php
use App\Services\Telegram\TelegramMarkdown;

public function __construct(
	// ...
	private readonly TelegramMarkdown $md,
) {}
```

### Вариант “быстро”

Вообще убрать `$this->md` и отправлять plain text (без Markdown). Но ты хотел “чёрную форму”, поэтому **не советую**.

## 2) Тип `role` в `TelegramUser`: enum или string

Это надо зафиксировать **однозначно**. Я предлагаю “как лучше”:

### Вариант A (рекомендую): Enum

`role` в модели — PHP enum `TelegramUserRole` с `value` (`admin|operator`).

Тогда **правильная строка**:

```php
$role = $tgUser?->role?->value ?? 'operator';
```

### Вариант B: string

`role` — просто string в БД и модели.

Тогда:

```php
$role = (string) ($tgUser?->role ?? 'operator');
```

✅ Убираем “двойной fallback” — он был защитным, но реально мешает.
**Выберите один вариант и придерживаемся его везде.**

---

## 3) `apiGet(url)` и endpoint в schema: нужен ли префикс

**Правило:** endpoint в schema должен быть **полным путём**, который UI вызывает напрямую.

Я предлагаю:

* schema возвращает endpoint вида: `"/api/webapp/api/history"` (уже с `/api`)
* тогда JS ничего не дописывает, просто делает `apiGet(endpoint + '?' + query)`.

Это проще и исключает рассинхрон.

---

## 4) `/api/webapp/api/schema` vs routes prefix `webapp/api`

Это стандарт Laravel:

* Все маршруты из `routes/api.php` автоматически имеют префикс `/api`.

Если в `routes/api.php` ты сделал:

```php
Route::prefix('webapp/api')->group(...)
```

То итоговый URL будет:

* ✅ `/api/webapp/api/schema`

**Вывод:** менять ничего не нужно, JS путь правильный.
В коде роута префикс `/api` добавлять НЕ надо — он уже добавляется Laravel.

## 5) Таблица `admin_actions`: миграция сейчас или позже

**Как лучше:** можно отложить, чтобы не тормозить запуск WebApp.

## 6) Экспорт: какой правильный путь

Если экспорт-контроллеры объявлены в `routes/api.php` под:

```php
Route::prefix('webapp/api')->middleware(['tg.webapp'])->group(...)
```

то URL экспорта будет:

* ✅ `/api/webapp/api/admin/export/accounts.csv`
* ✅ `/api/webapp/api/admin/export/issuance_logs.csv`

Значит:

* в JS правильно использовать `/api/webapp/api/admin/export/...`
* в routes оставляем как есть (без `/api`)
