## 1) Проверка `initData` (HMAC)

### 1.1 Реализация

Делаем **с нуля**, без внешних пакетов. Это 20–30 строк кода в Laravel middleware/сервисе.

### 1.2 Проверка expiry / timestamp

Да, проверяем:

* если в `initData` есть `auth_date` → считаем TTL
* **TTL = 24 часа** (86400 сек) по умолчанию
  (в прод можно снизить до 1–6 часов, но 24 нормально для старта)

**Если auth_date старше TTL → 401**.

---

## 2) Формат ответов WebApp API (единый стандарт)

Все API отвечают **только так**:

### Успех

```json
{ "ok": true, "data": {...}, "message": "optional" }
```

### Ошибка

```json
{ "ok": false, "error": { "code": "VALIDATION_ERROR", "message": "text", "fields": { "field": ["msg"] } } }
```

HTTP-коды:

* 200 — ok=true
* 401 — не авторизован / initData invalid
* 403 — нет прав (роль)
* 422 — валидация (ok=false + fields)
* 500 — внутренняя

## 3) История (`/webapp/api/history`)

### 3.1 Поля

Возвращаем:

* `id`
* `issued_at` (ISO 8601, UTC или app timezone)
* `order_id`
* `game`
* `platform`
* `account_id`

Оператору **не возвращать** email и скрытые поля.

### 3.2 Пагинация

Да. Формат:

* query: `?page=1&per_page=20`
* по умолчанию `per_page=20`, максимум `100`

Ответ:

```json
{
  "ok": true,
  "data": {
    "items": [...],
    "page": 1,
    "per_page": 20,
    "total": 123
  }
}
```

## 4) Поиск (`/webapp/api/admin/find`)

### 4.1 Параметры

Все **опциональные**:

* `game` (LIKE)
* `platform` (exact или LIKE — лучше exact если у нас фиксированный список)
* `status` (enum): `available|cooldown|disabled`
* `page`, `per_page`

### 4.2 Что считать статусами

* `disabled` → `is_active = false`
* `available` → `is_active = true AND available_uses > 0`
* `cooldown` → `is_active = true AND available_uses = 0 AND next_release_at > now()`

### 4.3 Пагинация

Да, как в истории.

### 4.4 Поля в выдаче админ-поиска

Возвращаем:

* `id`
* `platform`, `game`
* `game_login`
* `available_uses`, `max_uses`
* `next_release_at`
* `is_active`
* вычисленный `status`

## 5) Экспорт CSV

### 5.1 Кодировка

Делаем **UTF-8 с BOM**, чтобы Excel нормально открывал.

### 5.2 Какие экспорты

1. `accounts.csv` (только admin)

   * `id,platform,game,game_login,available_uses,max_uses,next_release_at,is_active,created_at`
   * **email поля по умолчанию НЕ экспортируем** (безопасность).
     Если нужно — сделаем отдельный “sensitive export” позже.

2. `issuance_logs.csv`

   * `id,issued_at,order_id,operator_telegram_id,account_id,game,platform`

## 6) Импорт файлом

### 6.1 Максимальный размер

* **до 2 MB** (для старта более чем достаточно)

### 6.2 Ошибки

**Построчно**, не валим весь файл:

* считаем `added / skipped / errors`
* `errors_preview` (первые 20 ошибок):

  * line_number
  * raw_line
  * message

Ответ:

```json
{
  "ok": true,
  "data": { "added": 10, "skipped": 2, "errors": 1, "errors_preview": [...] }
}
```

## 7) Валидация форм (front + back)

### 7.1 На фронте

Да — минимально:

* required
* number min/max
* pattern

### 7.2 На бэкенде

Обязательно (истина только тут):

* Request validation Laravel
* ошибки возвращаем в формате `ok=false` + `fields`

Кастомные сообщения не обязательны — дефолт Laravel ок.

---

## 8) Логирование действий WebApp API

Логируем **только админские** действия в отдельную таблицу (или в общий audit):

Минимум: `admin_actions`

* `id`
* `telegram_id`
* `action` (string)
* `payload` (json nullable)
* `created_at`
* `ip` (optional)

Что логировать:

* add account
* import
* enable/disable/reset
* user create/update
* export (можно без payload)

Операторские `history/me` можно не логировать.

# Приложение: готовый план “как делать” (без вопросов)

1. Middleware `VerifyTelegramInitData`

   * парсит initData
   * проверяет HMAC + TTL auth_date
   * кладёт `telegram_id` в request

2. WebApp API:

   * `GET /webapp/api/schema` (с учётом роли)
   * `GET /webapp/api/me`
   * `GET /webapp/api/history` (pagination)
   * admin endpoints (find/import/accounts/users/export)

3. WebApp UI:

   * tabs+forms из schema
   * submit bot: sendData JSON (issue)
   * submit api: fetch + render table/result

4. Bot:

   * принять `message.web_app_data.data`
   * action=issue → вызвать `IssueAccountsService` → ответить в чат code-block
